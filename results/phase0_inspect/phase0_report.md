# Phase 0 report: Gleason2019 training set inspection

Generated by `data/inspect_gleason.py --root data/gleason --out results/phase0_inspect` (no training).
All CSVs referenced below are in this folder.

## 0. Setup actions
- Data is in `data/gleason/` (not `data/gleason2019/`). `Train Imgs.zip` was **not** extracted; it was
  extracted to `data/gleason/TrainImgs/` (244 JPEGs).
- `Maps{k}_T.zip` → `data/gleason/Map{k}/` (one folder each). All zips are flat and every map uses the
  identical file name `slideXXX_coreYYY_classimg_nonconvex.png`, so a shared folder would have
  silently overwritten files. Each folder holds exactly the files its zip lists:
  Map1 244, Map2 141, Map3 242, Map4 244, Map5 246, Map6 65 (= 1182 files).

## 1. Structure and naming
- Images: `TrainImgs/slide{SSS}_core{CCC}.jpg`. Masks: `Map{k}/slide{SSS}_core{CCC}_classimg_nonconvex.png`.
  All 1182+244 names match these patterns. **core_id = `slide{SSS}_core{CCC}`.**
- 6 slides: 001 (44 cores), 002 (40), 003 (37), 005 (46), 006 (49), 007 (28). There is no slide004
  (probably the withheld test set; not verifiable).
- **Grouping:** slide is recoverable from the name. **Patient IDs are not in the release.** The source
  study (Nir et al., JAMA Netw Open 2019, same Vancouver cohort) reports 333 cores from 231 patients
  on 7 TMA slides, with "only 2 cores per patient". So some public training cores share a patient, and we
  cannot tell whether a patient's cores sit on the same slide.
- **Orphan masks (no image), excluded:** `slide007_core137` and `slide007_core145` in Maps 1–5, plus
  `slide006_core137` in Map4. Overlap tests could not match the Map4 orphan to any core lacking a Map4
  mask. With orphans removed: 242 + 139 + 240 + 241 + 244 + 65 = **1171 maps**, matching Foucart et al. (2021).

## 2. Image size and magnification
- RGB JPEG, no EXIF/DPI metadata. Sizes are multiples of 512: 5120×5120 (140), 4608×5120 (44),
  5120×4608 (21), 5120×5632 (14), 4608×4608 (12), 4608×5632 (6), 5632×5120 (5), 5632×5632 (2).
  So 512-px tiling divides every image exactly.
- Every mask has exactly its image's size (0 mismatches). Masks are 8-bit grayscale (`L`), single channel, with no PNG metadata.
- Magnification is not in the files. The source study says ×40 on a Leica SCN400. Tissue spans
  ~4400 px (4120–4712), i.e. ~1.1 mm if ×40 ≈ 0.25 µm/px. That is a plausible TMA core, so the images look native ×40.
  Tissue covers 48–65% of each image (median 59%).

## 5. Does each map folder correspond to one pathologist?
No contradicting evidence. Each folder shows a stable per-slide "signature":
- **Vocabulary:** only Maps 1 and 2 ever use value 6, and they do so on every slide. Map1 uses 6 where others use 1.
- **Map2:** 71–82% unannotated on every slide. Lowest leave-one-out kappa on every slide (0.25–0.32).
  Under-calls cancer extent on every slide. This matches Foucart et al.'s expert with mostly unclosed contours
  (only 20 of 139 maps clean). Foucart's per-expert map counts (237/20/186/235/244/64 clean) are consistent with Map k = Expert k.
- **Map1:** grades higher than the others' consensus on every slide (+0.12 to +0.32 mean grade). Most frequent G5 user.
- **Map5:** over-calls cancer extent on every slide (+0.09 to +0.17 area fraction).
- Map6's grade bias changes sign between slides, but it has only 5–16 cores per slide. Not conclusive.

Caveats: the zip timestamps are a single sequential export on 2019-07-11 (one block per map), so they cannot identify annotators.
Stable signatures support, but cannot prove, one pathologist per folder.
